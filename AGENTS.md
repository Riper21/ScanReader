# 🤖 AGENTS.md: Инструкции и Архитектурные Правила (ScanReader Modernized)

> **Назначение файла:** Главное руководство, свод архитектурных правил, инвариантов и протоколов разработки для AI-ассистентов в проекте распознавания судебных и исполнительных документов ScanReader.
> **Базовый стек:** Python 3.9+, Pydantic v2, OpenAI API / Ollama / vLLM (Qwen2.5-VL), Pillow, PyMuPDF, openpyxl, pandas, pytest.
> **Основной пакет:** `src/scan_reader/` (структура PEP 517/621, единый источник правды).
> **Контур безопасности:** Закрытый корпоративный периметр. Локальный кэш без утечек памяти и секретов.

## 2. Железные инженерные правила (Core Invariants)

### 🔴 Правило 0: Plan-First (Обязательное составление и утверждение плана)
* **Запрещено вносить любые изменения в код, схемы или плагины без предварительного составления детального плана и его утверждения.**

### 🔴 Правило 1: Нулевая терпимость к «тихим сбоям» (Zero Silent Failures)
* **Запрещен паттерн `except: pass`**.
* Все ошибки логируются через `get_logger()` и изолируются в возвращаемых структурах (`status: FAILED`, `errors: [...]`), не прерывая пакетную обработку остальных документов.

### 🔴 Правило 2: Zero-Trust верификация юридических данных (`verifier/`)
* **Никогда не доверять выходу VLM вслепую.**
* Все ИНН (10 и 12 знаков), СНИЛС (11 знаков), ОГРН/ОГРНИП, БИК и расчетные счета обязаны верифицироваться алгоритмическими контрольными суммами.
* Суммы (`debt_amount_rub + court_fee_rub == total_deduction_rub`) и пределы взыскания (50% / 70% по 229-ФЗ / ТК РФ) сверяются математическим верификатором.
* Даты процессуальных актов проверяются на хронологическую непротиворечивость.

### 🔴 Правило 3: Плагинная изоляция типов документов (`doc_types/`)
* Ядро системы не содержит жестко зашитых категорий документов.
* Каждый новый тип документа обязан оформляться в виде самодостаточного плагина в `doc_types/<type_id>/` с 7 обязательными файлами:
  `manifest.json`, `schema.py`, `prompt.md`, `classifier_rules.json`, `flat_columns.json`, `benchmark.json`, `autonomous.json`.

### 🔴 Правило 4: Безопасный парсинг вывода моделей (`_safe_parse_json`)
* Все ответы от VLM/LLM обязаны проходить через `_safe_parse_json` из `core.utils` с обязательной очисткой рассуждений `<think>...</think>` (Qwen/DeepSeek) и извлечением JSON из markdown code blocks.

### 🔴 Правило 5: Атомарный ввод-вывод и маскирование секретов (`core.io_utils`)
* Запись артефактов и отчетов производится атомарно через `write_atomic` (временный файл + fsync + замена) во избежание повреждения файлов при сбоях питания/процесса.
* Логирование и CLI сообщения автоматически фильтруют токены, пароли и паспортные данные через `mask_secret()`.

### 🔴 Правило 6: Строгое соответствие Pydantic-схемам (Schema Fidelity)
* Извлеченные данные валидируются через Pydantic v2 модели соответствующих плагинов.
* Модели Pydantic, содержащие слово `Test`, обязаны иметь атрибут `__test__ = False`.

### 🔴 Правило 7: Кроссплатформенная санитизация имен файлов и UTF-8
* При экспорте артефактов имена файлов очищаются через `sanitize_filename()`.
* Консольный вывод настраивается через `setup_console_utf8()`.

## 3. Протокол тестирования

Запуск полного тестового сьюта:
```powershell
py -3 -m pytest
```
Замер тестового покрытия пакета:
```powershell
py -3 -m pytest --cov=scan_reader --cov-report=term-missing
```
Проверка линтером:
```powershell
py -3 -m ruff check src/
```
