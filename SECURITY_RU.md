## 2. Архитектура безопасности и модель угроз

ScanReader обрабатывает конфиденциальные судебные акты, исполнительные листы и персональные данные граждан РФ (ФЗ-152). В архитектуре заложены следующие защитные рубежи:

### Работа в изолированном корпоративном периметре (On-Premise)
- Система может функционировать полностью автономно без подключения к интернету с использованием локальных VLM-серверов (Ollama, vLLM, Qwen2.5-VL).
- Вызовы внешних облачных API (OpenAI, DeepSeek) производятся только при явном указании в конфигурации `.env`.

### Защита персональных данных (ПДн)
- Все алгоритмы верификации (ИНН, СНИЛС, ОГРН, суммы, даты) исполняются детерминированно внутри процесса без отправки во внешние системы.
- Логирование оснащено функцией автоматического маскирования (`mask_secret`), скрывающей API-ключи, Bearer-токены и паспортные данные.

### Ограничение ресурсов и защита от DoS
- Входные файлы и тела запросов MCP ограничены лимитом `MAX_INPUT_BYTES = 50 МБ` для предотвращения переполнения памяти (OOM) и DoS-атак.
- Встроенный Token Bucket RateLimiter предотвращает перегрузку GPU при параллельных запросах.

### Отказоустойчивый ввод-вывод
- Сохранение JSON и Excel выполняется через временные файлы с принудительным `os.fsync` и атомарной заменой `os.replace`, что исключает риск повреждения баз данных при внезапном отключении электропитания.

При обнаружении уязвимости в ScanReader просим не публиковать её в открытых Issue, а направить конфиденциальное уведомление:

- **E-mail:** `security@organization.corp`
- **Регламент:** Подтверждение получения в течение 48 часов, план исправления — в течение 5 рабочих дней.
