## 1. Обзор системы и возможности

AI-платформа ScanReader (0.8.0) предназначена для автоматического извлечения структурированных данных из юридических, судебных и исполнительных документов в форматах **PDF (включая многостраничные сканы), JPG, PNG, TIFF, DOCX, DOC, RTF, TXT**.

### Ключевые преимущества:
- **Двухзональная архитектура (Dual-Zone):** объединяет визуальный анализ сканов (VLM) и глубокий текстовый парсинг (Text OCR/NLP) для достижения максимальной точности.
- **Интеллектуальный финансовый парсер:** точное распознавание сумм долга, госпошлин, неустоек, процентов, дробей (1/2, 1/3, 1/4) и удержаний из заработной платы.
- **Плагинная модульность (`doc_types/`):** каждый тип документа изолирован в отдельный плагин со своей схемой валидации Pydantic v2.
- **Dependency Self-Healing:** автоматическая проверка и доустановка библиотек при первом старте.
- **Умное кэширование (SHA-256):** экономия ресурсов и времени — повторный анализ неизмененного документа возвращается мгновенно без повторного обращения к нейросети.
- **Учет расходов и токенов (TokenUsageTracker):** детальная статистика затраченных prompt/completion токенов, TTFT (время до первого токена) и скорости генерации.

## 2. Системные требования

- **Операционная система:** Windows 10 / 11, Windows Server, Linux, macOS.
- **Python:** версия **3.9 или выше** (рекомендуется Python 3.10–3.12).
- **Пакетный менеджер:** `pip`.
- **(Опционально)** Локальный VLM-сервер: [Ollama](https://ollama.com/) (с моделью `qwen2.5-vl:7b` или выше) или сервер [vLLM](https://github.com/vllm-project/vllm).

## 4. Настройка подключения к нейросети (.env)

В корневой папке проекта расположен конфигурационный файл `.env` (если его нет, создайте его на основе `.env.example`).

### Вариант А: Локальная модель Ollama (рекомендуется для закрытого контура)
1. Установите Ollama с официального сайта: [ollama.com](https://ollama.com)
2. Загрузите VLM-модель командой в терминале:
   ```powershell
   ollama run qwen2.5-vl:7b
   ```
3. В файле `.env` укажите:
   ```ini
   OPENAI_BASE_URL=http://localhost:11434/v1
   AI_MODEL_NAME=qwen2.5-vl:7b
   OPENAI_API_KEY=dummy_local_key
   ```

### Вариант Б: Локальный сервер vLLM / LM Studio
```ini
OPENAI_BASE_URL=http://localhost:8000/v1
AI_MODEL_NAME=Qwen/Qwen2.5-VL-7B-Instruct
OPENAI_API_KEY=dummy_local_key
```

### Вариант В: Облачные API (OpenAI GPT-4o, DeepSeek, OpenRouter)
Для использования OpenAI GPT-4o:
```ini
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=sk-proj-ВАШ_КЛЮЧ_OPENAI
```

### Сценарий 1: Drag & Drop (перетаскивание мышкой)
Самый быстрый способ распознать документ или целую папку:
1. Захватите файл документа (PDF, скан JPG/PNG или DOCX) или папку с документами мышкой в Проводнике Windows.
2. Перетащите его прямо на файл `scripts\windows\1_ОБРАБОТКА_ДОКУМЕНТОВ.bat` (или на `launcher.py`).
3. Система автоматически:
   - Определит тип документа (Судебный приказ, Исполнительный лист, Взыскание на зарплату и др.).
   - Распознает все реквизиты, должников, взыскателей и финансовые суммы.
   - Сохранит JSON в папку `output/`.
   - Создаст и откроет готовый отчет Excel.

### Сценарий 7: Автономный запуск (Silent CLI) и интеграция с 1С / скриптами

Для встраивания распознавания в учетные системы (**1С:Предприятие / 1С:ЗУП**), фоновые службы, скрипты автоматизации PowerShell/Bash или бэкенд-сервисы предназначена отдельная консольная утилита **`cli.py`**.

Она работает в полностью автономном («тихом») режиме:
* **Не открывает** окна Проводника Windows и графические диалоги.
* В стандартный поток вывода (`stdout`) печатает **только одну строку** — абсолютный путь к созданному файлу JSON (или само тело JSON при передаче флага `--format stdout`).
* Все технические логи, прогресс и предупреждения направляет в поток ошибок (`stderr`), благодаря чему `stdout` вызывающей системы гарантированно защищен от служебного мусора.
* Возвращает стандартные системные коды завершения (Exit Codes): `0` — успех, `1` — файл не найден / ошибка обработки, `2` — ошибка синтаксиса аргументов CLI, `3` — обнаружены расхождения Zero-Trust (требуется ручная проверка), `4` — сработал эвристический фолбэк.

#### 1. Стандартный запуск из командной строки (возврат пути к 1C JSON):
```powershell
py -3 cli.py "C:\Scans\Постановление_10701.pdf"
# Вывод в stdout:
# C:\ScanReader\output\Постановление_10701_1c.json
```

#### 2. Запуск в PowerShell с сохранением пути в переменную:
```powershell
$jsonPath = py -3 cli.py "C:\Scans\Постановление_10701.pdf"
Get-Content $jsonPath | ConvertFrom-Json
```

#### 3. Вывод самого тела JSON напрямую в поток stdout (без чтения с диска):
```powershell
py -3 cli.py "C:\Scans\Постановление_10701.pdf" --format stdout
```

#### 4. Пример прямого вызова из 1С:Предприятие 8.3 (BSL):
```bsl
// Формирование команды запуска в тихом режиме:
КаталогПроекта = "C:\ScanReader";
ПутьКСкану     = "C:\Scans\Постановление_10701.pdf";
Команда = "py -3 """ + КаталогПроекта + "\cli.py"" """ + ПутьКСкану + """";

// Вызов утилиты и перехват stdout:
WshShell = Новый COMОбъект("WScript.Shell");
Процесс = WshShell.Exec(Команда);
Вывод = Процесс.StdOut.ReadAll();
ПутьКJSON = СтрЗаменить(Вывод, Символы.ПС, "");
ПутьКJSON = СокрЛП(ПутьКJSON);

// Чтение сформированного JSON и создание документа 1С:
Если ФайлСуществует(ПутьКJSON) Тогда
    Чтение = Новый ЧтениеJSON;
    Чтение.ОткрытьФайл(ПутьКJSON);
    Данные1С = ПрочитатьJSON(Чтение);
    Чтение.Закрыть();
    // Создание документа "Исполнительный лист" в 1C:ЗУП...
КонецЕсли;
```

#### Параметры командной строки `cli.py`:
| Параметр | По умолчанию | Описание |
| :--- | :--- | :--- |
| `scan_path` | *(обязательный)* | Путь к файлу скана / документа (PDF, JPG, PNG, TIFF, DOCX) |
| `-f, --format` | `1c` | Формат вывода: `flat` / `1c` (путь к плоскому JSON для 1С `_Flat.json`), `full` (путь к `_Full.json`), `both` (пути к обоим файлам), `default` (основной JSON карточки), `raw` (служебный JSON), `stdout` (печать текста плоского JSON в консоль) |
| `-t, --type` | `auto` | Принудительный тип документа (`salary_deductions`, `executive_documents`, `enforcement_orders`) |
| `-o, --output-dir` | `output/` | Пользовательский каталог для сохранения результатов |
| `-v, --verbose` | `false` | Выводить подробные логи процесса обработки в `stderr` |

## 6. Структура результатов и двухфайловый канонический формат JSON

Все готовые выгрузки сохраняются в папку **`output/`** (с обратной совместимостью с `Результаты/`). Для каждого документа формируются строго два канонических JSON-файла:

### 🌟 Основные форматы выдачи:
1. **`{Имя_Файла}_Full.json` — Полный иерархический JSON:**
   - Содержит полное дерево извлеченных реквизитов (стороны, суд/ФССП, должник, взыскатель, финансы).
   - Включает полный отчет независимого аудитора **Zero-Trust** (`zero_trust`, `zero_trust_status`, статус валидности).
   - Содержит метрики качества (`quality_score_percent`, `quality_status`), защитные шлюзы (Guardrails) и технические метаданные.
2. **`{Имя_Файла}_Flat.json` — Одноуровневый плоский JSON для 1С:**
   - 100% одноуровневая структура без вложенных словарей — сразу готов для импорта объектом `ПрочитатьJSON(Чтение)` в 1С:Предприятие / 1С:ЗУП.
   - Даты приведены к стандарту ISO (`YYYY-MM-DD`).
   - Финансовые суммы нормализованы к числам (float/int).
   - Для постановлений о взыскании на зарплату содержит строгий 1С-набор полей PascalCase (`Bik`, `PaymentAccount`, `ResolutionDate`, `ExecutiveDocumentNumber`, `ExecutiveDocumentDate`, `RospFullCode`, `Uin` и др.).
   - Содержит флаги верификации: `ZeroTrustStatus`, `ZeroTrustValid`, `QualityScore`.

### 📂 Сводные реестры:
- **`Registry_Full.json`** — консолидированный реестр всех обработанных документов в полном формате.

## 7. Поддерживаемые типы документов и плагины

Система построена на модульной плагинной архитектуре (`src/scan_reader/doc_types/`). Из коробки доступны:

1. **`enforcement_orders` — Судебные приказы и постановления:**
   - Номер судебного приказа, дата вынесения, судебный участок / мировой судья.
   - Должник (ФИО, дата и место рождения, паспорт, СНИЛС, ИНН, адрес).
   - Взыскатель (наименование/ФИО, реквизиты, ОГРН/ИНН, счет).
   - Суммы: основной долг, проценты, пени, неустойка, госпошлина, общая сумма.

2. **`executive_documents` — Исполнительные листы:**
   - Серия и номер ИЛ, дата выдачи, суд выдачи, номер судебного дела.
   - Предмет исполнения, резолютивная часть.
   - Взыскатель и должник со всеми идентификаторами.
   - Взыскиваемые суммы и порядок взыскания.

3. **`salary_deductions` — Постановления об обращении взыскания на заработную плату:**
   - Номер и дата исполнительного производства (ИП), подразделение ОСП / ФССП.
   - Первичный судебный акт-основание: наименование (`base_doc`), номер (`base_doc_number`), дата (`base_doc_date`) и суд выдачи.
   - Судебный пристав-исполнитель (ФИО, звание/должность).
   - Должник и место его работы (работодатель, адрес).
   - Процент удержания (например, 50%, 70%, 25%), очередность платежей, банковские реквизиты для перечисления.

4. **Универсальный режим (Universal Fallback):**
   - Для любых прочих документов (акты, письма, договоры, справки) — извлекает базовые реквизиты, стороны, даты и суммы.

## 8. Устранение неполадок (FAQ / Troubleshooting)

### ❓ Ошибка: `Connection refused` или `Failed to connect to localhost:11434`
**Решение:** Убедитесь, что сервер Ollama запущен. Запустите Ollama через ярлык или выполните команду `ollama serve` в терминале.

### ❓ Ошибка: `Model 'qwen2.5-vl:7b' not found`
**Решение:** Модель еще не скачана в Ollama. Выполните команду:
```powershell
ollama pull qwen2.5-vl:7b
```

### ❓ Ошибка: `ModuleNotFoundError: No module named 'pydantic'` (или другой модуль)
**Решение:** Запустите `scripts\windows\УСТАНОВИТЬ_ЗАВИСИМОСТИ.bat` или выполните:
```powershell
py -3 -m pip install -r requirements.txt
```

### ❓ Документ плохого качества / размытый скан
**Решение:** Встроенный модуль `file_processor.py` автоматически выполняет авто-контрастирование (`ImageEnhance.Contrast`), авто-ориентацию (`ImageOps.exif_transpose`) и адаптивное масштабирование DPI для сканов.
